# 产品体验质量门禁

## Product Experience Brief

设计页面前先记录：

```text
目标用户：谁在使用
触发场景：何时、何地、因为什么进入
核心任务：用户真正想完成什么，而不是点击哪个按钮
期望结果：完成后获得什么价值或确定性
当前摩擦：耗时、重复输入、信息缺失、风险、等待或焦虑
频率与风险：高频/低频，可逆/不可逆
非目标：第一版明确不解决什么
体验目标：用真实测试可观察什么
```

事实不足时标记 `unknown` 或 `inferred`，每轮只询问 1–3 个最影响产品形态的问题。

## 功能价值判断

每个 MVP 功能必须同时具备目标用户、触发场景、核心任务、预期结果和关联 ACxx。出现以下任一情况时先删减或延后：

- 只是竞品有、模板有或视觉上好看。
- 不能缩短用户完成任务的路径，也不能降低风险或提升结果质量。
- 只服务极低频高级场景，却增加所有用户的理解成本。
- 与现有能力重复，或需要用户先理解内部技术结构。

## 旅程与页面决策卡

为每个核心旅程和页面记录：

| 项目 | 必须回答 |
| --- | --- |
| 用户目标 | 此刻想完成什么 |
| 入口 | 用户怎样发现并进入 |
| 信息优先级 | 先做哪个决定，后看什么细节 |
| 主操作 | 唯一主要下一步是什么 |
| 系统反馈 | 点击后立即、等待中和完成后分别看到什么 |
| 失败恢复 | 错在哪里、如何修正、是否保留已输入内容 |
| 退出与撤销 | 怎样安全返回、取消或撤销 |
| 信任 | 数据来源、权限、风险和后果是否清楚 |
| 验收 | 用哪个 ACxx 和真实操作证明 |

## 好体验的可观察标准

- **第一次成功**：新用户能从自然入口理解价值并完成最小任务，不依赖培训或内部术语。
- **高频效率**：减少重复输入、无意义确认和跨页往返；保留必要安全步骤。
- **认知清晰**：信息按用户决策顺序组织，一个页面一个主任务，高级能力渐进披露。
- **状态可见**：系统始终说明正在做什么、是否成功、数据是否保存和下一步是什么。
- **错误可修复**：错误靠近原因，保留有效输入，给明确恢复动作，不只显示错误码。
- **结果可预测**：危险或不可逆操作提前说明影响，默认值可解释，支持撤销时优先支持撤销。
- **信任与包容**：权限、隐私、数据来源和风险透明；键盘、读屏、对比度、触控与 reduced motion 成立。
- **主观感受**：视觉、文案和动效降低压力并匹配产品主题，但不以装饰掩盖流程问题。

## 验收方法

至少用目标用户视角走一次首次旅程和一次失败恢复。记录入口是否被发现、实际步骤、耗时、犹豫点、误解、失败原因、恢复结果和用户原话。没有真实观察时只写“待验证”，不能编造成功率、满意度或节省时间。
