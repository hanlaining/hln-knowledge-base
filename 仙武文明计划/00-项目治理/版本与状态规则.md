# 版本与状态规则

## 时间规则

所有正式Markdown必须同时保存：

```yaml
created: YYYY-MM-DD
updated: YYYY-MM-DD
created_at: YYYY-MM-DDTHH:mm:ss+08:00
updated_at: YYYY-MM-DDTHH:mm:ss+08:00
timezone: Asia/Shanghai
```

日期用于快速阅读，精确时间用于还原个人心路和知识库迭代顺序。

## 语义版本

采用 `主版本.次版本.修订版本`：

- 主版本：文明方向、系统边界或核心机制发生变化；
- 次版本：新增重要能力、模块、型号或机制；
- 修订版本：文字澄清、链接修正和不改变含义的补充。

示例：

```text
0.1.0：第一版概念草案
0.2.0：新增功法安全分级体系
0.2.1：补充术语解释
1.0.0：存在经过验证的完整最小闭环
```

## 版本升级条件

### CAB主版本

至少满足一种：

- 知识、权限或多智能体调度范式改变；
- 人类治理层和AI执行层的关系改变；
- 从单机原型进入分布式网络；
- 从软件任务进入物理设备控制。

### MAP主版本

至少满足一种：

- 人机控制方式发生根本改变；
- 从虚拟角色进入实体外附设备；
- 从随动辅助进入共享自主；
- 能源、材料或多域结构发生代际变化。

### 机甲型号升级

型号大改时建立下一代型号，不在原型号中无限堆能力。通用底座升级归入MAP版本；任务特定升级归入型号版本。

## 成熟度等级

| 等级 | 名称 | 判断依据 |
| --- | --- | --- |
| TRL-0 | 文明构想 | 只有愿景与概念 |
| TRL-1 | 原理假设 | 关键原理能够被表达 |
| TRL-2 | 数字模型 | 可在文档或仿真中运行 |
| TRL-3 | 软件原型 | 有最小可运行程序或游戏原型 |
| TRL-4 | 实验装置 | 有受控环境硬件样机 |
| TRL-5 | 场景验证 | 在限定真实场景完成任务 |
| TRL-6 | 系统试验 | 多模块长时间协同运行 |
| TRL-7 | 产品试点 | 面向小规模真实用户 |
| TRL-8 | 规模部署 | 具备生产、维护与监管体系 |

当前整个计划处于 `TRL-0`，部分数字人、机器人仿真、外骨骼和虚拟角色技术本身已处于更高等级，但不能因此推断完整仙武文明已经具备对应成熟度。
