# 知识库使用说明

## 目的

本知识库用于长期保存、拆分和演进“仙武文明计划”。它既是思想档案，也是未来研究、产品、游戏和工程原型的设计底稿。

## 文件类型

| 类型 | 用途 | 是否允许大胆设想 |
| --- | --- | --- |
| 总纲 | 定义长期方向和基本原则 | 允许，但需说明边界 |
| 架构 | 描述组件及其关系 | 需要保持逻辑一致 |
| 机制 | 描述权力、收益、权限和反馈 | 必须考虑副作用 |
| 版本 | 记录某一阶段系统能力 | 必须保留历史版本 |
| 型号 | 记录某一具体机甲产品族 | 必须有明确任务边界 |
| 假设 | 记录尚未验证的科学或工程条件 | 必须写明验证方式 |
| 讨论归档 | 保存想法形成过程 | 可以保留开放表达 |
| 路线图 | 将长期构想拆成阶段 | 必须有阶段出口条件 |

## 文档元数据

每份正式文档顶部使用：

```yaml
---
title: 文档标题
type: vision | architecture | mechanism | version | model | hypothesis | archive | roadmap
status: idea | hypothesis | researching | prototype | validated | deprecated
version: 0.1.0
created: YYYY-MM-DD
updated: YYYY-MM-DD
created_at: YYYY-MM-DDTHH:mm:ss+08:00
updated_at: YYYY-MM-DDTHH:mm:ss+08:00
timezone: Asia/Shanghai
---
```

其中：

- `created_at` 记录文件首次进入知识库的精确时间；
- `updated_at` 记录最近一次实质修改时间；
- 使用ISO 8601格式并保留时区；
- 当前统一时区为 `Asia/Shanghai`；
- 不知道准确历史时间时必须写“待补”，不能编造。

## 内容状态

- `idea`：构想，尚未进行系统论证；
- `hypothesis`：已形成可讨论假设，但未验证；
- `researching`：正在收集证据、建模或比较方案；
- `prototype`：已经有可运行的实验原型；
- `validated`：在定义的条件和范围内通过验证；
- `deprecated`：已被替代，但为保留历史而不删除。

## 新增内容流程

```text
灵感出现
→ 写入讨论归档或开放问题
→ 判断属于文明、机制、AI、机器人、机甲还是功法
→ 建立专题文档
→ 标注事实、推论与假设
→ 形成版本或型号
→ 更新索引和变更日志
```

## 事实层级

每份技术文档尽量区分：

1. **现有事实**：当前技术已经能够实现；
2. **合理外推**：根据当前研究能够推测，但尚未完整实现；
3. **关键假设**：必须取得材料、能源、物理或制度突破；
4. **文化表达**：用于形成东方仙武文明的审美与叙事。

## 版本与型号的关系

```text
机甲平台版本
描述共同操作系统、接口和能力底座
        ↓
具体机甲型号
针对贴身、重型、救援、深海等任务进行取舍
```

```text
AI中央大脑总体架构
定义长期不轻易改变的原则
        ↓
CAB具体版本
记录每一阶段真正具备的能力和限制
```

## 文件命名

- 专题：`主题-v0.1.md`
- AI大脑版本：`CAB-v主版本.次版本-代号.md`
- 机甲平台版本：`MAP-v主版本.次版本-代号.md`
- 机甲型号：`XW-类别编号-代号-定位-v版本.md`
- 功法：`GF-类别编号-名称-v版本.md`
- 讨论：`YYYY-MM-DD-主题-讨论纪要.md`

## 不删除历史

原则上不覆盖重大旧方案。若方向改变：

- 新建版本；
- 在旧文档中标记 `deprecated`；
- 在变更日志中写明替代关系；
- 保留当时为什么作出该判断的记录。
